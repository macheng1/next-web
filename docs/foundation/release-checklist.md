# 生产发布和回滚检查

## 发布前

- pnpm install --frozen-lockfile；pnpm run check 通过。构建验收用独立 .next-verify，正式发布使用 pnpm run build。
- NEXT_PUBLIC_SITE_URL、MEMBER_API_URL 是实际 HTTPS 地址，DEPLOYMENT_ENV=production；敏感变量仅服务端，环境文件不入库。
- 反向代理限制请求体、连接时长和速率，覆盖转发头；验证实际域名不是只看进程启动。
- 网关或后端对登录、找回密码、上传执行共享限流；至少用两个网站实例验证频率累计和 429，再记录 RATE_LIMIT_MODE。
- 外部维护一份限流核验 JSON（不含密钥）：mode（gateway/backend）、verifiedAt（ISO 时间）、evidenceReference（规则和核验记录编号）。设置 RATE_LIMIT_VERIFICATION_FILE 为该文件绝对路径。pnpm run check:production 会检查结构、匹配模式和 30 天有效期；文件声明不能替代实际测试。
- 核查修改接口外站 Origin 被拒绝，同站可提交；未经校验上传被拒绝，上传失败可重试。
- 检查 HttpOnly/Secure/SameSite Cookie；会员失效、后端不可用、两会员切换时的数据隔离。
- 用生产构建检查 CSP 无脚本通配/unsafe-eval，页面无 CSP 错误；地图如启用，验证实际厂商脚本链，不能以关闭 CSP 代替处理。
- 桌面及手机检查中文/英文、键盘、错误重试与文件预览。
- 检查 robots/sitemap/canonical：开发不收录、私有不收录、新网站真实公开页面允许收录。
- 配置线上存活、就绪探针及脱敏日志收集；明确告警联系人和触发策略。
- 运营在网站管理→首页管理→协议管理核对网站中英文条款、隐私政策和版本，保存草稿后选择“发布网站协议”；首页与页脚、网站协议、小程序协议分别发布，不相互覆盖。小程序协议配置目前仅后台维护，不替换现有小程序授权提示。注册请求必须携带实际展示的已发布协议版本。
- 后端负责人核查数据隔离、上传最终验证、邮箱投递、Token 撤销；运维核查数据库/文件备份并执行恢复演练。网站代码不会自动完成这些外部工作。

## 发布后

用实际域名检查首页、登录页、/api/health/live、/api/health/ready 和关键提交；验证版本、浏览器无错误、日志关联追踪编号。CI 成功或首页 200 不代表会员、数据库和上传已验证。

## 回滚

保留发布前的应用镜像/构建产物和配置版本；失败时切回上一个版本，恢复匹配的环境配置。邮箱会员和买家来源存在数据库迁移；先核对目标库版本，保留来源数据，停用新代码后再评估迁移回滚。协议配置与已发布历史保存在 web_catalog_home JSON 中，不要覆盖或删除。回滚后再次检查域名、健康检查、会话、关键提交。不能删除用户文件或生产数据作为回滚步骤。

## 本轮不包含

第三方登录、独立设备会话管理、网站订单支付履约、企业入驻入口、线上网关部署、实际告警配置和备份执行。网站邮箱注册、买家询盘与协议读取已接入；邮件投递和真实跨端业务仍须联调。相关入口不得以未完成按钮上线。

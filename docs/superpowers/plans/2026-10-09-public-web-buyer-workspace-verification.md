## 执行决定及实际限制

- 依用户确认的计划在原工作区编辑，保留之前的未提交登录改动；未提交、推送、合并或部署。风险：审阅提交时需要区分原改动与本批内容。
- 事务上下文+触发器统一来源，不重写每条交易 SQL。直接收藏/通知另传来源。风险：必须先迁移再运行新代码。
- 来源指认证 API 渠道；旧客户端缺 Header 从该渠道补足，不代表设备认证。权限始终由 JWT/会员归属判断。
- 客户端草稿只在当前设备保存，重复采购用独立 ID；不会跨设备自动同步。
- 系统通知排除聊天重复事件，避免总未读重复；通知批量已读使用明确 ID 快照。
- 网站入驻退役后，旧相关测试改为重定向/入口不存在；地区组件测试仍独立挂载，不恢复网站入口。
- 没有迁移或连接生产库，没有发送真实供应商消息或邮件，没有主动重启已有服务。真实接口使用前需执行 `1710000042400-buyer-request-source` 并更新后端；需按发布流程完成真实会员/企业联调。

# 企业官网资料与手动英文维护 Implementation Plan

**Goal:** 企业登录后可维护企业、类目、产品英文；官网按语言展示并逐字段回退中文。
**Architecture:** 沿用企业 JSON translations，类目及规格扩展相同结构。英文参数绑定中文参数，规格 ID 不变。公共接口仅投影公开字段。
**Tech Stack:** NestJS / TypeORM / PostgreSQL、Ant Design、Next.js / Tailwind。

- [x] 接口：类目、产品维度与规格英文；局部更新保留未传译文，空字符串清空；公开字段逐项回退。补充回归测试。
- [x] 企业端：类目双语输入、产品参数及规格配对维护，企业资料区分主体信息、官网展示与英文资料。桌面布局。
- [x] 官网：企业封面及 logo、简介分层、公司资料全文、隐藏无内容模块；企业内分类筛选和分页。
- [x] 验证：后端测试/构建、企业端构建、官网类型/静态检查/测试/隔离构建及浏览器验证。

本轮不接入翻译服务，不提交、推送或部署。不改动现有生产数据。不公开账号、电话及证照编号。

## 验证记录

- 后端：397 项测试通过，构建成功。覆盖类目英文创建/省略/清空，局部翻译更新，旧数组合同迁移，历史中文参数保护，英文维度歧义校验，分类页与计数一致。
- 官网：60 项单元测试、24 项浏览器检查通过；typecheck、lint、隔离构建通过。320/768/1440 宽度、中英文、分页及空模块有覆盖。
- 企业端：生产构建成功，12 项会话测试通过；隔离模拟接口验证类目改名/清空、资料回显、参数/规格英文提交，以及维度删除后的中英文对应关系。
- 本地真实接口只读检查：中文/英文企业列表、详情、产品列表均 HTTP 200；浏览器实际核对企业主页与公司资料。未修改真实业务记录。
- 企业端完整类型检查仍有现存 `.ice` runtime 与 Axios interceptor 依赖类型错误；本轮修改的表单/服务无新增类型错误。

## 处理约定

- 复用中文企业简称作为官网展示名称，新增 JSON 英文展示名称，主体全称单独展示，无新增数据库列。
- 旧版英文参数数组接受读取与写入，保存后迁移到中文参数行；数组整份替换，字符串空值清空，未传字段保留。
- 企业内自定义分类筛选使用 enterpriseCategoryId，与平台分类 category 分开。
- 证照当前没有明确的公开发布字段，本轮不将原有证照照片或编号投影到官网，避免把内部审核材料变为公开资料。

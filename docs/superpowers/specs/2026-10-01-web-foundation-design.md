# 国际网站通用底座设计

日期：2026-10-01。分支：dev。状态：待用户评审，尚未实施。

## 1. 目标与边界

补齐网站通用基础能力，为后续国际访客网站提供可复用接口、安全约束、组件和工程检查。沿用 Next.js App Router、React、TypeScript、Tailwind 和 Semi UI。旧业务不作为新业务实现模板；本次不开发产品、询盘、企业入驻、运营管理等业务，也不删除尚被使用的路由。

对外网站、企业平台和内部运营平台仍是三个独立入口。公共买家注册与企业审核申请分开。当前后端注册接口属于企业审核申请，本轮只保留兼容适配，不包装成公共注册。第三方登录需后续后端身份接口及服务商配置，本轮不展示无法完成登录的按钮。

## 2. 方案选择

推荐：保留技术框架，建立模块化共享底座，通过兼容适配替换现有重复实现。优点是能复用组件和后端，逐步验证；成本是需要维护短期适配层。

备选一：逐页修补。短期改动少，但重复错误处理和安全规则仍会分散，不满足复用要求。

备选二：整体换框架、认证和组件库。结构可重新统一，但迁移范围大、后端对接成本高，本次没有采用的理由。

## 3. 已核实的现状

- Next.js 16.1.1、React 19、Semi UI 19；已有主题变量和 Semi 按钮、弹窗包装。
- API_URL 对接门户后端，MEMBER_API_URL 对接会员后端，两者路径前缀不同。
- Token 已存 HttpOnly Cookie；后端提供受保护的 GET /web/members/me，可用于验证当前会话。
- 浏览器接口和服务端代理仍存在重复错误解析、追踪编号与配置逻辑。
- 中英文词典已有基础；根 HTML 固定 en，语言匹配规则未统一。
- 安全头只在 vercel.json 设置，CSP 放行范围过宽；自部署缺少统一策略。
- robots 指向尚未实现的 sitemap；没有统一自动测试和 CI 检查入口。

## 4. 模块与复用规则

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| config | 验证服务端配置与公开配置 | 密钥不进入浏览器构建；两套后端分别配置 |
| http | 超时、取消、统一响应、错误和追踪编号 | 浏览器只访问同源代理；不允许调用者指定任意代理目标 |
| server/backend | 对接两套后端 | 路径白名单、请求字段白名单、敏感头过滤 |
| auth | 会话读取、验证、退出、登录失效反馈 | 后端为身份依据；页面隐藏按钮不是授权 |
| security | 来源校验、请求大小、限流接口、安全头 | 后端仍负责最终授权与数据隔离 |
| i18n | 语言匹配、词典、格式化、Semi 语言包 | 默认中文，支持英文，非法语言回落 |
| components | 通用状态和必要的薄包装 | Semi 原有交互、键盘与焦点能力交给组件库 |
| observability | 脱敏日志、追踪、健康检查 | 不记录 Token、密码或表单正文 |
| tests/CI | 验证基础约束与构建 | 不依赖真实生产账户和第三方服务 |

文件按上述职责组织在 src/lib、src/components 和 src/app 内，保持现有别名。业务 API 通过共享底座适配，不另建第二套请求体系。服务端模块使用 server-only，防止被客户端导入。

### 组件规则

直接使用 Semi 的 Input、Form、Select、Checkbox、Modal、SideSheet、Toast、Notification、Spin、Skeleton、Empty、Typography 等。保留有明确作用的现有 Button 包装；只为统一主题、表单错误呈现和组合布局增加包装。包装继续暴露必要的原组件属性，不为每个控件重新定义一套接口。

将通用弹窗和隐私告知组合分离。通用弹窗的关闭行为不能被隐私场景固定；隐私组合单独定义告知与拒绝操作。共享状态包含加载、无数据、失败重试、无权限、会话过期、404 和全局异常。禁止遗留中文默认文案直接进入英文页面。

## 5. 请求和会话

统一区分网络失败、超时、取消、HTTP 错误和业务错误；业务 code 失败不能因为 HTTP 200 被视为成功。允许 GET 做有限重试，提交类请求默认不自动重试。FormData 不手动设置 Content-Type。调用链透传统一追踪编号，来源字段采用已有 portal-web 约定，仅用于记录来源，不用于鉴权。

登录结果继续只在服务端写 Cookie，不把 Token 返回浏览器。Cookie 保持 HttpOnly、SameSite、生产 Secure；有效期不超过后端有效期。服务端保护入口请求后端 me 验证会话，并禁用私有数据缓存。后端明确拒绝凭证时清理无效 Cookie；后端临时不可用时显示服务错误，不误当退出。

本地退出清理网站 Cookie。后端没有已核实的退出撤销接口，因此不宣称已支持全设备退出。权限按后端返回并经后端校验，不在浏览器伪造角色。个人资料缓存不能跨用户共享。

## 6. 安全设计

所有修改请求统一校验 Origin 与配置的可信网站来源，结合 SameSite；来源缺失的浏览器修改请求拒绝。若未来需要非浏览器客户端，另设显式认证通道。后端代理目的地址固定，禁止用户传入任意 URL；外部链接仅接受允许协议。涉及 HTML 的内容必须经过明确的清理策略，不能直接信任来源。

Next 配置统一安全头，自部署与平台部署使用同一来源配置。生产 CSP 明确允许所需脚本、图片和连接来源；开发调试例外独立配置，不能混入生产。HSTS 仅在确认使用 HTTPS 的生产配置启用。验证框架安全公告后决定补丁升级，不盲目改大版本。

共享上传校验负责允许类型、大小、数量、文件名和实际内容检查，并与现有上传后端对齐。上传权限及文件最终校验仍由后端执行。下载链接限制协议及允许域名，不返回任意服务端文件路径。

提供可替换的限流接口与开发内存实现；生产多实例使用后端或网关的共享限流能力。没有共享限流接入时在发布检查中明确阻止把内存限流标记为生产保护完成。统一限流错误及 Retry-After；成功前不登记重复提交完成。

## 7. 多语言与体验

复用 zh/en 词典，建立统一语言列表、解析和回落规则；URL 内有效语言优先，其次有效 Cookie，再按 Accept-Language 匹配，最后中文。非法语言不得继续组成重定向路径。

统一 Intl 日期、数量、金额格式，金额必须带明确币种，不隐含汇率换算。Semi LocaleProvider 随语言切换。文档语言与实际界面一致，基础错误和通知支持中英文。后续业务文案需通过词典补齐，不能将底座完成等同于所有旧页面已翻译。

保留现有主题变量，统一焦点、禁用、加载和触达尺寸；支持键盘、减少动画偏好、桌面与手机布局。缺省图及图标优先使用已有资源和组件库。

## 8. SEO、性能与运行

站点地址必须配置为真实域名。共享元信息工厂提供标题、描述、canonical、语言替代地址和分享元信息；只列出真实且允许索引的页面。账号和私有页不索引，开发环境不索引。robots 与 sitemap 使用同一站点配置，禁止生成示例域名。

明确公开内容缓存和私有内容 no-store 的边界；使用 Next Image、字体与按需加载能力。根级错误恢复、404 和加载状态采用共享组件。健康检查只暴露最小状态，不泄露配置；存活与依赖就绪分开，依赖异常返回失败状态。

脱敏日志关联追踪编号，记录错误分类与耗时。外部错误收集可通过适配器接入，未配置时保留本地脱敏日志。告警通道、备份恢复、网关防护、邮件投递和数据保留执行需要部署及后端配合，本轮提供清单与接入边界，不宣称前端已完成这些运维能力。

## 9. 验证与交付

增加统一 typecheck、lint、单元测试、构建检查及 CI。重点测试配置缺失、语言回落、超时取消、HTTP 200 业务失败、来源拒绝、会话失效、缓存隔离和安全头生产/开发差异。浏览器验证基础状态、语言切换、键盘操作及桌面/手机尺寸。

提供 .env.example、模块使用说明、组件复用目录、生产检查和回滚说明。密钥不进入提交；只记录配置名称和占位示例。实现阶段先配置/接口/安全，再会话/多语言，再组件/SEO，最后完整验证。实施完成的报告分别列代码已完成项、运行验证项和仍需外部配置项。

验收标准：新增页面能直接使用共享请求、会话、语言、状态组件；接口规则不再逐页复制；秘密只留服务端；基础失败状态可复现验证；CI 可在无生产凭证条件下通过。后续业务开发及第三方登录另行设计。
